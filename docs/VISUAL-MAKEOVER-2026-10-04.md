# BloodLink visual makeover — local design review

Base: `0a83b1f44e9bd82e538e664ddac0cc7fbe184e0f`. Work remains local, unstaged and uncommitted. No deployment, push, backend edits, AWS changes or production data mutations.

1. **Direction:** modern clinical SaaS, with off-white pages, neutral surfaces, deliberate BloodLink red, compact operational typography and generous page gutters.
2. **References:** [Tabler](https://github.com/tabler/tabler) informed the restrained navigation, compact metrics, table rhythm and theme tokens; [shadcn-admin](https://github.com/satnaing/shadcn-admin) informed quiet surfaces and the page/action hierarchy; [TailAdmin](https://github.com/TailAdmin/tailadmin-free-tailwind-dashboard-template) informed responsive dashboard composition. These are native Blazor implementations; no template, CSS framework or React code was imported.
3. **Tokens:** `wwwroot/css/design-tokens.css` owns backgrounds, surfaces, borders, foregrounds, brand/hover/soft colors, five semantic status palettes, focus, inverse surfaces, radii, shadows, spacing, font stack, control height, page gutters and motion timing. Existing variable names are compatibility aliases. Dark mode uses `prefers-color-scheme`.
4. **Typography:** Inter-first, local system fallback, with no font download or runtime CDN. Page titles are 30px desktop and 25px mobile; body/controls 14–15px; section headings 16–20px; metadata generally 12–13px. Weights distinguish normal text, controls, sections and page titles.
5. **Icons:** the existing Lucide renderer is retained and extended with official local geometry. Navigation icons are 20px with a consistent 2px stroke. Refresh, logout, history, dashboard, staff, adjustments, toast severity and dismiss controls now share it. BloodLink's droplet/cross remains a brand mark. License notices are in `LUCIDE-LICENSE.txt`.
6. **Buttons:** brand primary, neutral secondary/outline/ghost, semantic success and destructive danger, compact/normal/large sizes, icon controls, hover feedback, disabled states and visible focus. Public registration CTAs are primary; destructive operations retain danger. Hover no longer shifts control geometry.
7. **Forms:** shared field height, neutral boundaries, readable labels/help, blue focus ring, disabled treatment and semantic validation styling. Plain operational forms and EditForms now share the same visual language. Staff creation, need creation, adjustments and availability search have contextual introductions. Existing fields, validation and submissions are preserved.
8. **Badges:** neutral/info/success/warning/danger use soft token backgrounds and retained status wording. Searching/Sent use info; pending/urgent use warning; fulfilled/accepted use success; emergency/rejected/suspended use danger. This changes only status color presentation. Blood types use small consistent tokens.
9. **Sidebar:** 248px neutral desktop sidebar, subtle dividing border, workspace/account headings, consistent icons, compact navigation, tinted active state, and separated identity/logout area. Mobile brand, account placement, drawer handlers, Escape behavior and session guards remain intact.
10. **Dashboard:** four compact operational metrics for facility admins, followed by a distinct inventory band showing the existing total/available/unread values, then needs awaiting review and recent activity. Role-specific SystemAdmin and FacilityStaff summaries remain. No new API requests or invented metrics.
11. **Tables:** quiet headers, row separators, hover treatment, tabular numbers, numeric alignment and concise action buttons. Fixed desktop column layout and wrapping handle narrow desktop widths and long names. Labeled mobile record cards and request-specific mobile cards are preserved.
12. **Inventory:** blood type, total, reserved and available stock are easy to scan. Stock conditions retain text and semantic badges. Calculations, thresholds, reservation behavior and adjustment payloads remain unchanged.
13. **Needs:** consistent blood-type tokens, urgency/status hierarchy, shared details, actions and readable status timeline. Existing action availability, creator/role rules, deadline validation and workflow are unchanged.
14. **Requests:** shared details and mobile cards, clearer values and status treatment, consistent decision fields, reserved-stock context, handover confirmation and final-state presentation. Full-amount acceptance, rejection reason, cancellation and transfer behavior are preserved.
15. **Activity:** existing events have a restrained audit timeline treatment and readable timestamp/summary hierarchy. Dashboard activity uses the shared compact empty state. Event order, latest-five behavior, pagination and API calls are unchanged.
16. **Staff/facility:** common headers, forms, status badges, record actions and confirmations. The duplicate staff-create CTA was removed because the same action remains in the page header. System administration has explicit platform context. Existing permissions and lifecycle handlers are unchanged.
17. **Public:** quieter hero/feature composition, improved type and spacing, restrained healthcare image framing and a neutral footer. Existing locally stored WebP, text purpose, navigation and fragment behavior remain.
18. **Login/registration:** branded login panel and centered mobile form; desktop healthcare image aside preserved. Registration retains its two logical fieldsets, all fields, aliases, validation messages and submit semantics, with clearer typography and spacing.
19. **Dark mode:** neutral slate surface tiers, accessible foregrounds, themed inputs/tables/badges/sidebar/dialogs/toasts and public/auth pages. Brand-filled buttons use dark foregrounds in dark mode. No inversion filter or external theme dependency.
20. **Responsive:** 320, 360, 375, 390, 430, 768, 1024, 1280, 1440 and 1920px in both themes. Checks cover document overflow, clipped controls, narrow fields, long operational content, record card breakpoints, history placement and drawer geometry. Tablet table width and 320px activity wrapping were corrected during review.
21. **Accessibility:** visible focus, preserved labels and semantic controls, retained textual statuses, labeled icon controls and reduced-motion support. Automated WCAG 2 A/AA and 2.1 A/AA rules are run through axe; token contrast checks cover text, semantic badges, field boundaries and focus. Keyboard order, Escape, menu toggles, dialog focus/restoration, logout and route transitions are checked separately. Automated checks supplement visual and keyboard review; they do not constitute an external certification.
22. **Changed files:** page/layout/shared component markup; `wwwroot/index.html` and `app.css`; browser verification scripts and their development package manifest/lockfile. The complete list is saved in `artifacts/ui-parity/visual-makeover-2026-10-04/git-status.txt`.
23. **Added/removed:** added design token and clinical presentation sheets, Lucide license, local fixture module, design-system verifier, operational flow verifier and this report. Added axe-core only as a verifier development dependency. Removed the unused template `wwwroot/css/app.css` after confirming it was not referenced. Removed duplicate token ownership and two duplicate CSS rules; existing responsive layout contracts remain in `wwwroot/app.css`.
24. **Tests:** restore passed; Release build passed with zero warnings/errors; all 108 existing tests passed; format verification passed; NuGet vulnerability scan found no vulnerable packages; npm installation/audit reported zero vulnerabilities; diff whitespace check passed. Results are consolidated in the local verification summary.
25. **Browser verification:** every existing browser verifier was exercised locally: public, public-local, public-production, public-routing, authenticated, service-worker-cleanup, facility-filter, notification-toasts, activity-history, mobile-operational, login-drawer and the CDP UI-parity verifier for all three roles. Production-oriented verifiers use local targets; auth/public fixtures intercept API traffic. Their legacy report filenames do not indicate a production deployment or live-backend verification.
